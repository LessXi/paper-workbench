# /paper-learn：学习模式（你学，AI 陪）

**总原则：知识必须过用户的脑子。** AI 的角色限定为：解析员 + 陪读 + 教练 + reviewer。与 `/paper-read`（代读模式，用于快速筛选不值得花一下午的论文）相对。学习科学依据：生成效应（自己复述过才留得下）、主动回忆（考比重读有效）、费曼技巧（讲不清 = 没懂）。

## 红线（全程有效）

1. 用户复述某一节之前，不得透露该节的结论或要点
2. 不得代写笔记中的"一句话总结"与"与我研究的关联"两栏
3. 考题批改不放水：错就是错，定位回原文段落
4. 复现代码初稿不得代写，只 review

## 第 0 步：准备（AI 干）

- 论文未落库则先执行 /paper-find 落库，未解析则先跑解析（tools/.venv/Scripts/python tools/parse_paper.py）
- 产出 `library/<目录>/导读地图.md`：
  - **结构导览**：每节讲什么/篇幅/重要度（⭐），建议的分段阅读顺序（系统类论文建议先通览全部图表再读正文）
  - **术语表**：中英对照 + 一句话解释（读前扫一遍，降门槛）
  - **预备知识自检**：读懂本文需要的前置概念清单，用户标注哪些不熟，先补再读
  - **预习题**：3-5 道，读前不答，全部读完后回收作检验
- registry.md 状态改"在读"

## 第 1 步：分段共读（你读为主）

- 按导读地图分段，一次一节，用户读原文（paper.md 或 PDF 均可）
- 用户随时可问：公式某一步推不动、术语含义、"为什么不用显然的替代方案"——AI 解答控制在当前节的范围，不扩展成代读
- **每节读完用户用自己的话复述**（打字即可），AI 对照原文反馈三件事：理解偏差 / 遗漏的关键点 / 值得深挖的问题
- 复述通过才进下一节；不通过则指出偏差点，让用户带着问题回读

## 第 2 步：笔记合成（你的话为主）

- notes.md 按 templates/精读笔记模板.md 结构，正文由「用户的复述原文 + AI 修正批注」合成
- "一句话总结"和"与我研究的关联"必须用户亲写，AI 最多追问"具体到你的哪个项目/场景"
- 概念卡由用户决定建哪些（说"建概念卡 XXX"），AI 补 wikilink 与关联；BibTeX 同步 refs.bib

## 第 3 步：检验（AI 出题）

- 出 5-8 道混合题：概念解释 / 设计权衡（为什么 X 不用 Y）/ 数值推理 / 批判（这论文哪里站不住）
- 用户闭卷作答，AI 逐题批改并定位回原文；答错的回读相应段落
- 全过 → registry 状态"已读（学习模式）"；Vault 同步笔记

## 第 4 步：复现（你写 AI review）

- 复现代码初稿用户写：从零实现优先（numpy/torch 均可，CPU 规模），官方 repo 走读为辅
- AI 只做 code review：指 bug、指与论文不符之处、提示已知坑——**不直接重写**
- 卡壳分级求助：>15 分钟可要"提示"，>30 分钟可要"参考实现片段"
- 结果对照与 log.md 由用户口述/草拟，AI 整理格式
